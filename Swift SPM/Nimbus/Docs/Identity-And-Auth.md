# Identity & Auth

Covers: ECID lifecycle, the launch gate order (Consent → Login → Main tabs), guest mode, and logout behavior.

Related: [Services API](Services-API.md) for the `IdentityService` protocol · [Surfaces & Triggers](Surfaces.md) for what's tracked around login.

## ECID: created on install, not on login

The ECID (Experience Cloud ID) is generated by the AEP Edge Identity extension the first time the SDK initializes — on the app's first launch, before any consent choice or login. It is not tied to a signed-in user.

- Anonymous users have an ECID with no linked identity.
- Signing in links an `Email` identity item to that same ECID (see below) — it does not create a new one.
- Logging out unlinks the `Email` item but keeps the same ECID. Uninstalling the app is the only thing that produces a new ECID on the next install.

The app reads the ECID once at launch via [`AppEnvironment.refreshIdentity()`](../Nimbus/App/AppEnvironment.swift), which calls [`IdentityService.experienceCloudId()`](../Nimbus/Services/IdentityService.swift). It's displayed in [`LoginView`](../Nimbus/Features/Login/LoginView.swift) and [`ProfileView`](../Nimbus/Features/Profile/ProfileView.swift) as `env.shortECID`.

## Launch gate order

[`RootView`](../Nimbus/App/RootView.swift) decides what to show at launch, in this order:

1. **`ConsentPrimerView`** — shown once, until `hasChosenConsent` is set. Consent is not a device flag; declining still lets the ECID exist and be sent to Edge (see [Consent](../Nimbus/AEPIntegration/Consent/AEPEdgeConsentService.swift) — `.pending` is never actively sent, so the tag property's default consent setting governs until the user picks yes/no).
2. **`LoginView`** — shown once, until `hasSeenLoginPrompt` is set. Skipped automatically on relaunch if an authenticated `Email` identity item is already present in the Identity Map (checked in `refreshIdentity()`).
3. **`MainTabView`** — Home / Shop / Inbox / Profile.

Login is never a hard requirement — Guest mode is a first-class path, not a fallback.

## Login

[`LoginView`](../Nimbus/Features/Login/LoginView.swift) collects an email and calls `env.login(username:)`, which:

1. Calls [`IdentityService.login(username:)`](../Nimbus/AEPIntegration/Identity/AEPEdgeIdentityService.swift), which builds an `IdentityMap` with the email under the standard `Email` namespace, `authenticatedState: .authenticated`, `primary: true`, and calls `Identity.updateIdentities(with:)`.
2. Sets `signedInUser` and `hasSeenLoginPrompt` on `AppEnvironment` so the UI reflects the signed-in state immediately.

`Identity.updateIdentities` only updates the local identity map — it doesn't call Edge by itself. The email reaches AEP's identity graph on the next Edge event this session sends.

This is a local, unauthenticated demo login — there is no backend auth call. Its purpose is to exercise identity linking, not to model a real auth system.

## Guest mode

Tapping "Continue as Guest" calls `env.continueAsGuest()`, which only sets `hasSeenLoginPrompt = true`. No identity item is added — the user stays anonymous on the existing ECID. Guests can use every tab; personalization and messaging still work off the anonymous ECID.

## Logout

[`ProfileView`](../Nimbus/Features/Profile/ProfileView.swift)'s "Log out" button calls `env.logout()`, which calls [`IdentityService.logout()`](../Nimbus/AEPIntegration/Identity/AEPEdgeIdentityService.swift):

- Reads the current Identity Map and removes every item under the `Email` namespace via `Identity.removeIdentity`.
- The ECID is never touched — logout only unlinks the email, it does not reset the device identity.
- This only clears the **local** identity map. The `Email` ↔ ECID link already sent to the server-side identity graph is permanent; a future login from the same device will re-link the same graph.

After logout, `signedInUser` is cleared in `AppEnvironment`, but `hasSeenLoginPrompt` stays `true` — the user goes straight back to the main tabs as a guest, not back to `LoginView`.
